# 원격기 동등성 스택 — 통합 벤치 체크리스트

> **문서 요약**: `feat/remote-status-bits` 스택(main 위 23커밋, 요구사항 A·B-1~B-5·C 전항목)의 **HW 검증 항목을 한 장으로 모은 것**이다. 스테이지마다 spec 이 따로 있고 검증 항목이 그 안에 흩어져 있어, 사용자가 "전부 구현하고 한 번에 시험" 방식을 택한 이상 벤치 당일 spec 5개를 뒤지게 된다 — 그것을 없애는 것이 이 문서의 목적이다. 항목은 **실행 순서대로** 배열했고 각 항목에 mbpoll 명령·판정·근거 스테이지·실패 시 의심 커밋을 붙였다. 앞부분(§0~§2)은 **읽지 않고 벤치에 들어가면 반드시 사고가 나는 전제**들이다: 보드에 남아 있는 설정 잔재, SWD halt 금지, mon 이 보이는 조건, 빌드 2종(STD/REMOTE), 그리고 **PC8 인터록 스위치가 실장된 PCB 가 아직 없다**는 것. 배선 미비로 이번 벤치에서 **할 수 없는 항목은 §6 에 분리**했다 — 시도했다가 "실패"로 오판하지 않기 위해서다.

**작성**: 2026-09-04
**대상 스택**: `feat/remote-status-bits` (`4c92e0c`..`c5c2f7e`)
**상태**: 미실행 — 보드 미확보

## 0. 전제 (읽지 않고 들어가면 사고 난다)

### 0.1 보드에 남아 있는 상태 (2026-08-17 세션 말미)

| 항목 | 값 | 주의 |
|---|---|---|
| `comm_mode` | **ETH_STATIC, IP .199** | SERIAL 이 아니다. RTU 항목은 LCD 로 전환 후 |
| serial 파라미터 | **38400 / EVEN** | ⚠ 구 기록의 9600 이 아니다 |
| `cal_val` | **16** | 🔴 **사용자 의도 트림 — 원복 금지.** CAL 항목이 이 값을 건드리므로 §5 에서 반드시 되돌릴 것 |
| `freq_cal_val` | **40** | 🔴 동일 |
| 펌웨어 | main `ec1b972` 상당(STD) | 스택 미탑재 |

### 0.2 금지·제약

- 🔴 **런타임 검증에 SWD gdb halt 금지.** `sys_tick` 이 멈춰 hang/`ch1=0`/`run=0` 오진을 부른다 — 2026-06-28 세션이 이것으로 대부분 낭비됐다. SWD 는 **플래시 또는 부팅 직후 정적 read 1회**만.
- **mon(USART6 115200 8N1)은 `comm_mode` 가 ETH_* 일 때만 보인다.** RTU 가 점유하면 `apply_config` 가 `mon_set_enabled(false)` 를 건다. → "Modbus 는 TCP + 모니터는 RS-485 청취" 구성이 성립하고, 게이트 로그를 보려면 그 구성이어야 한다.
- **Modbus TCP 소켓은 1개.** 예전엔 stale ESTABLISHED 가 칩 KA 로 **~20초** 뒤에야 풀렸는데, **앱 유휴 타임아웃 `MB_TCP_IDLE_MAX_MS`(12초)를 신설**해 이제 12초에 컨트롤러가 먼저 끊고 재리슨한다(`3ce1ead`). → ⚠ **폴링을 12초 이상 쉬면 연결이 끊긴다.** mbpoll 을 띄워 두고 오래 손 놓았다가 "죽었다"고 오판하지 말 것 — 재접속하면 된다.
- **mbpoll `-r` 은 1-based.** wire 주소 + 1 이다 (`0x1D` → `-r 30`). 아래 표의 숫자는 전부 mbpoll 기준.
- mbpoll 플래그는 인라인으로 쓸 것(zsh word-split 회피).

## 1. 준비

### 1.1 빌드 2종

```bash
./fw.sh                 # STD    -> build/         (게이트 없음)
MODEL=remote ./fw.sh    # REMOTE -> build-remote/  (게이트 있음)

# PC8 스위치 미실장 보드에서 REMOTE 를 벤치할 때:
cd fw && env -u STM32_TOOLCHAIN cmake -B build-remote-bypass -G Ninja \
    -DMODEL=REMOTE -DREMOTE_EN_GATE_BYPASS=ON
```

⚠ **BYPASS 없이 REMOTE 를 스위치 미실장 보드에 올리면 모든 원격 명령·cfg 쓰기가 막혀 벤치가 죽는다.** 부팅 mon 에 `*** REMOTE ENABLE GATE BYPASSED ***` 가 찍히는지로 어느 빌드인지 구분할 것.

### 1.2 어느 빌드로 무엇을 보나

| 빌드 | 볼 수 있는 것 |
|---|---|
| **STD** | S · M · B34 · FA · CAL 전부. **게이트가 없어 방해받지 않는다 → 기본 빌드로 시작할 것** |
| **REMOTE + BYPASS** | 위 + 게이트 미러(0x2A/0x2B) 관측, 단 강제는 꺼져 있음 |
| **REMOTE (순정)** | A 섹션 전체. **PC8 실장 PCB 필요** |

## 2. 실행 순서와 이유

```
S (스모크·무회귀)  →  M (모델 축)  →  B34 (STATUS 비트)  →  MOD  →  CAL  →  NET  →  FA (comm/eth)  →  A (게이트)
```

- **S 먼저**: 스택이 기존 동작을 깨지 않았다는 것을 확인하기 전에 신규 기능을 보면, 실패했을 때 원인이 신규인지 회귀인지 못 가른다.
- **FA 를 뒤로**: comm/eth 커밋은 **통신 설정 자체를 바꾼다.** 앞 항목을 다 끝낸 뒤에 해야 링크가 바뀌어도 남은 시험이 없다.
- **A 를 맨 뒤**: 게이트가 켜지면 이후 모든 쓰기가 게이트에 걸린다.

## 3. 항목

### S — 스모크 / 무회귀 (STD 빌드)

| # | 항목 | 절차 | 판정 |
|---|---|---|---|
| S-1 | 부팅 | 전원 인가, mon 관측(ETH 모드) | 배너 + `[eth] up`, 리셋 루프 없음 |
| S-2 | FC03 전수 읽기 | `mbpoll -m tcp 192.168.1.199 -r 1 -c 50 -1` | 50칸 응답, 값이 LCD 화면과 일치 |
| S-3 | 직접런 ceiling | `-r 28 1` 쓰기 → `-r 30` 폴링 | STATUS bit0 이 1 유지하다 **약 514~578 ms** 후 0 (실측 구간) |
| S-4 | FC06 클램프 무회귀 | `OUT_POWER(-r 7)` 에 30 / 120 쓰기 | 각각 50 / 100 으로 read-back |
| S-5 | LCD 육안 | ICON_RUN, 값 3종 | 화면과 FC03 일치 |
| **S-P** | **원격 START 진폭 pot write** (신규 `ac7e691`) | comm=ETH_STATIC + **RS-485 mon 청취** 상태에서 `OUT_POWER(-r 7)` 를 부팅값과 다른 값(예 80)으로 쓴 뒤 `-r 28 1` | mon 에 `[lcd-hook] set_pot power=80 …` 1줄 + STATUS bit0=1 → ceiling 정지. ⚠ **부팅값과 같은 55/56 으로 시험하면 회귀를 못 잡는다** — 그것이 이 결함이 6월부터 벤치를 통과한 이유다. 실패 시 의심 = `ac7e691` |

### M — 모델 축 (신규)

| # | 항목 | 절차 | 판정 |
|---|---|---|---|
| M-1 | STD 버전 문자열 | LCD 버전 표시 | `V3.0.0_260725` |
| M-2 | REMOTE 버전 문자열 | REMOTE 빌드 플래시 후 | `V3.0.0R_260725` — **R 접미어로 구분** |
| M-3 | STD 는 CAP 를 안 싣는다 | STD 빌드에서 `-r 43` 에 `0x1234` 쓰고 read-back | **`0x1234` 가 그대로 남음** (미러 없음 = 구 펌웨어와 동일 판정. **의도된 동작**) |
| M-4 | REMOTE 는 CAP 매직 복원 | REMOTE 빌드에서 같은 조작 | `0x5201` 로 복원됨 |

### B34 — STATUS 관측 비트 (STD 빌드로 충분)

| # | 항목 | 절차 | 판정 |
|---|---|---|---|
| B34-1 | HORN 비트 OFF | horn 모드 꺼진 상태에서 `-r 30` | bit6(`0x40`) = 0 |
| B34-2 | HORN 비트 ON | LCD STD SETUP 에서 horn-down 모드 ON → `-r 30` | bit6 = 1 |
| B34-3 | **차단 사유 관측** | bit6=1 상태에서 `-r 28 1`(START) | STATUS `us`=0 유지 **+ bit6=1 로 사유 설명됨**. ⭐ **이 항목이 B-4 의 존재 이유다** |
| B34-4 | HORN 비영속 | horn ON 상태에서 전원 재인가 | bit6 = 0 (재부팅 시 소실 — 설계대로) |
| B34-5 | 기존 5비트 무회귀 | S-3 재실행하며 `-r 30` 관측 | bit0 만 토글, 상위 비트 오염 없음 |
| B34-6 | SENSOR 비트 | — | ⚠ **§6 로 이연** (센서 배선 없음) |
| B34-7 | **horn 원격 ON** (B-4 조작) | `-r 49 1` 쓰기 | read-back=1 + **STATUS bit6=1** + LCD 화면이 horn 모드로 |
| B34-8 | horn 원격 OFF | `-r 49 0` | read-back=0 + bit6=0 |
| B34-9 | 전이 시 솔 강제 OFF | horn ON→OFF 전이 관찰 | mon `[weld] SOL_DN OFF` 또는 솔 육안 — 전이마다 무조건 OFF |
| B34-10 | **비영속** | horn ON 상태로 재부팅 | `-r 49` = 0 (설계대로 소실 — 누락 아님) |
| B34-11 | horn 중 START 차단 + 사유 관측 | bit6=1 상태에서 `-r 28 1` | `us`=0 유지 **+ bit6 로 사유 설명** ⭐ B-4 의 목적 |

### MOD — 모델 선택·주파수 원격 쓰기 (B-5)

⚠ **`model_type` 쓰기는 PC11 의 의미를 바꾼다** — 가드 없음(2026-09-04 사용자 결정, LCD 경로와 동형). 아래 MOD-4 를 **E-stop 배선이 있는 리그에서만** 시도할 것.

| # | 항목 | 절차 | 판정 |
|---|---|---|---|
| MOD-1 | 읽기 무회귀 | `-r 24`, `-r 25` | LCD 화면과 일치 |
| MOD-2 | **주파수 쓰기** | `-r 24 2` (30 kHz) | read-back = 2 + **LCD 모델명이 `GDS-30…` 으로 갱신** |
| MOD-3 | **타입 쓰기** | `-r 25 2` (std) | read-back = 2 + LCD 모델명 접미 `S` |
| MOD-4 | ⚠ 파생 상태는 즉시 안 바뀐다 | MOD-3 직후 LCD 런페이지 관찰 | **옛 페이지 유지**가 정상. `sys_mode`·런페이지·출력바 임계는 다음 부팅/SYS_PIC_NOW 에서 갱신 (LCD 편집 경로와 동일) |
| MOD-5 | 범위 밖 퇴화 | `-r 24 99` | 저장은 99, 모델명은 **15 kHz 표기로 퇴화**(switch default). 크래시·깨진 문자열 없음 |
| MOD-6 | 🔴🔴 **E-stop 해제 확인** — 아래 경고 필독 | model_type=2 로 둔 뒤 PC11 HIGH(E-stop 활성) → `-r 25 0` 쓰기 | E-stop 이 **해제**된다(가드 없음 = 의도된 동작). 예상과 다르면 설계 재검토 |
| MOD-7 | 영속 | MOD-2/3 후 재부팅 | 새 값 유지 + 그때 런페이지·모델명이 새 모델로 |

> 🔴🔴 **MOD-6 은 살아있는 비상정지를 의도적으로 해제하는 시험이다.**
> 기계가 실제로 기동 가능한 상태가 되므로 **초음파·솔레노이드 부하를 분리한 상태에서만** 수행할 것. 사람이 기계 가동부 근처에 없어야 한다.
> 컨트롤러는 이 요청을 **거부하지 않는다**(2026-09-04 사용자 결정 — LCD 경로에도 같은 가드가 없어 원칙 일관성을 택했다). 원격기(`gds_us_remote`)는 자기 안전 계층(`REJ_ESTOP`)으로 이 경로를 막고 있으나 **그것은 원격기 경로에만 적용된다** — mbpoll 같은 임의 마스터에는 방벽이 없다. 이 항목이 바로 그 노출을 확인하는 것이다.
> 거부가 필요하다는 판단이 나오면 들어갈 자리는 `app_modbus.c` 의 `MODEL_TYPE` 분기 주석에 명시돼 있다(`app_estop_active() || us_on_status`).

### FA — comm/eth staging + commit

⚠ **여기서부터 통신 설정을 실제로 바꾼다.** 앞 섹션을 모두 끝낸 뒤 진행.

| # | 항목 | 절차 | 판정 |
|---|---|---|---|
| FA-1 | 기본 상태 | 부팅 직후 `-r 31 -c 12` | `CFG_STAT(-r 42)`=0, staged 9종이 cfg 값 미러 |
| FA-2 | staged 쓰기가 실계에 무영향 | `-r 32 3`(COMM_SPEED) 쓰기 | read-back=3 **+ LCD comm 페이지 변화 없음** + `CFG_STAT`=**1**(STAGED) |
| FA-3 | 재부팅 시 구 값 | FA-2 상태로 재부팅 | 구 값 복귀 (FRAM 미반영 확인) |
| FA-4 | DISCARD | `-r 41 2` | 미러 복귀 + `CFG_STAT`=0 |
| FA-5 | **교차 커밋 (TCP→serial)** ⭐ | TCP 접속 상태에서 serial 그룹 staged → `-r 41 1` | `CFG_STAT`=**2** + **TCP 링크 생존** + 새 파라미터로 RTU 재접속 성공 |
| FA-6 | **교차 커밋 (RTU→ether)** ⭐ | RTU 접속 상태에서 IP staged → 커밋 | `CFG_STAT`=2 + **RTU 링크 생존** + 새 IP 로 TCP 접속 성공 |
| FA-7 | same-link 거부 (RTU) | RTU 접속 중 serial 그룹 커밋 | `CFG_STAT`=**4** + cfg 불변 + **RTU 생존** |
| FA-8 | same-link 거부 (TCP) | TCP 접속 중 ether 그룹 커밋 | `CFG_STAT`=4 + cfg 불변 + TCP 생존 |
| FA-9 | 범위 거부 + **부분 커밋 없음** | `COMM_SPEED=3`(유효) **와** `COMM_ADDR=0`(무효) 둘 다 staged → 커밋 | `CFG_STAT`=**3** + **SPEED 도 반영 안 됨** |
| FA-10 | 가동 중 거부 | START 로 가동 중 커밋 | `CFG_STAT`=**5** + cfg 불변 |
| FA-11 | 타임아웃 | staged 후 **30초** 방치 | `CFG_STAT`=**6** + 미러 복귀 |
| FA-12 | 링크 전이 폐기 | staged 상태에서 RTU↔TCP 전이 | staging 폐기 + 미러 복귀 |
| FA-12b | 🔴 **타임아웃이 성공으로 안 보고됨** | staged 후 30초 방치(`CFG_STAT`=6) → 그 상태로 `-r 41 1` 커밋 | **`CFG_STAT` = 6 유지**. ⚠ `2`(COMMIT_OK)가 나오면 마스터가 "새 IP 적용됨"으로 오판하는 버그가 되돌아온 것(`3ce1ead` 수정분) |
| FA-13 | `CFG_CTRL` 잔류 없음 | `-r 41 7`(정의 안 된 값) 쓰기 → read-back | **0** (값 불문 소거 — 유령 pending 커밋 방지) |
| FA-14 | `comm_mode` 쓰기 불가 | `-r 34 1` 쓰기 → read-back | 미러가 덮어 **원래 값** |
| FA-15 | 영속 | 커밋 후 재부팅 | 새 값 유지 |

⭐ **FA-5 · FA-6 이 이 스펙의 핵심이다** — 교차 경로 커밋이 실제로 링크를 살려두는지가 DG-12 설계의 전제다.

### NET — TCP 연결 자동 복구 (STD 빌드로 시험 가능, PC8 불요)

사용자 요구 "스위치가 켜져있다면 통신연결은 자동 복구되어야 함" 반영분(`3ce1ead`).

| # | 항목 | 절차 | 판정 |
|---|---|---|---|
| NET-1 | 유휴 타임아웃 동작 | TCP 접속 후 **12초 이상** 아무 요청도 보내지 않음 | mon 에 `[mbtcp] idle 12s -> disconnect (재리슨)` + 소켓이 끊김 |
| NET-2 | 재접속 가능 | NET-1 직후 재접속 | **즉시 성공** (예전의 ~20초 대기 없음) |
| NET-3 | 🔴 **KA 구멍 회복** | TCP 로 접속만 하고 **한 프레임도 안 보낸 채** 클라이언트를 강제 종료(`kill -9` 등) → 재접속 시도 | **12초 뒤 접속 성공.** ⚠ 수정 전에는 W5500 KA 가 무-데이터 연결을 커버하지 않아 **ESTABLISHED 영구 고착 → 전원 재인가 전까지 접속 불가**였다. 이 항목이 그 회귀를 잡는다 |
| NET-4 | 정상 폴링 무영향 | 1초 주기 폴링을 5분 유지 | 끊김 없음 (타임아웃이 정상 트래픽을 건드리지 않음) |

### A — 원격 활성화 게이트 (**PC8 실장 PCB 필요**)

| # | 항목 | 절차 | 판정 |
|---|---|---|---|
| A-1 | 스위치 OFF = 불허 | `-r 44` | `0` (DISABLED) |
| A-2 | 명령 차단 | OFF 상태에서 START/SEEK/RESET | STATUS 무변화 + 레지스터 소거 + mon `[mb] gate closed(state=0)` + **`[sr]` OSC 구동 0건** |
| A-3 | cfg 쓰기 차단 | OFF 상태에서 FC06 | "Written" 에코하되 **read-back 이 미러로 복원** |
| A-4 | **STOP 상시 통과** | OFF 상태에서 STOP | mon `blocked=0x00 stop_passed=1` |
| A-5 | 스위치 ON = 허용 | 스위치 닫음 → `-r 44` | `1` (ENABLED), 명령 통과 |
| A-6 | **만료 없음** | ON 상태로 **10분 이상** 방치(폴링 계속) | `-r 44` 계속 `1`. ⚠ 옛 설계의 600초 창이 남아 있으면 여기서 `2`로 떨어진다 |
| A-7 | 링크 침묵 해제 | ON 상태에서 폴링 **10초 이상** 중단 | `-r 44` = `3` (DIS_LINK) |
| A-8 | 🔴 **링크 해제 자동 복귀** | A-7 후 **스위치는 그대로 두고** 폴링만 재개 | **`1` 로 복귀** — 사람이 스위치를 만지지 않아도 된다. ⚠ 여기서 `3` 이 유지되면 **옛 래치 코드가 남은 것**(`0e723de` 의 자기교착, `3ce1ead` 에서 수정) |
| A-9 | 복귀 후 재침묵 | A-8 후 다시 10초 침묵 | 다시 `3` — 무장이 유지돼야 성립 |
| A-10 | E-STOP 해제 | ON 상태에서 E-STOP 누름 | `-r 44` = `4` (DIS_ESTOP) |
| A-11 | 🔴 **E-STOP 래치는 유지** | E-STOP 해제, 스위치 ON 유지, **폴링 계속** | **`4` 유지** — 트래픽이 와도 안 열린다. 링크와 달리 안전 이벤트는 사람의 재확인을 요구한다 |
| A-11b | **스위치 사이클 재무장** | A-11 상태에서 스위치 OFF→ON | `0` 거쳐 `1` 로 복귀 |
| A-12 | E-STOP 레벨 차단 | E-STOP 누른 채 스위치 OFF→ON | `4` — 열리지 않는다 |
| A-13 | **fail-safe 단선** | 🔴 스위치 배선을 물리적으로 분리 | `-r 44` = `0` (**불허**). 여기서 `1` 이 나오면 **극성이 뒤집힌 것 — 회로 수정 필요** |
| A-14 | `0x2C` 결번 | `-r 45` | 항상 `0` |
| A-15 | 커밋 게이트 연동 | 게이트 OFF 에서 `CFG_CTRL=1` | `CFG_CTRL` 소거됨 + **`CFG_STAT` 불변** + cfg 불변 |

🔴 **A-13 이 이 섹션에서 가장 중요하다.** 인터록의 안전 성질 전체가 "단선 = 불허"에 걸려 있다. 옵토(TLP181)가 극성을 한 번 뒤집으므로 회로 검토만으로 확신하지 말고 **실제로 선을 뽑아서** 확인할 것.
