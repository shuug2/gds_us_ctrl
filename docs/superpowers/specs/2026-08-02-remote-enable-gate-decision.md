# 원격 제어 활성화 게이트 — 결정 기록 (gds_us_remote 발) 

> **문서 요약**: `gds_us_remote`(ESP32-P4 원격 컨트롤러) 프로젝트에서 2026-08-02 사용자가 승인한 결정을 이 저장소에 기록한다. 핵심은 두 가지다. ① **이 펌웨어에 원격 제어 권한 게이트가 전혀 없다는 사실이 확인됐고**, Modbus에 도달 가능한 누구나 언제든 `START(0x1B)`를 쓸 수 있다. 물리 인터록도 없다(현장 확인). 이를 막기 위해 **컨트롤러 LCD에서만 켤 수 있는 원격 활성화 게이트**를 신설한다(레지스터 `0x2A~0x2D`). ② 별도로 **Modbus 미노출 저장변수(comm/ethernet)를 `0x1E~0x29`에 노출**한다. 두 작업은 승인 게이트와 주소 공간이 분리돼 서로 비의존이다. **아직 구현 착수 전이며 이 문서는 요구사항 전달과 결정 근거 보존이 목적**이다. 설계 정본은 `gds_us_remote` 저장소에 있다.

## 1. 왜 이 문서가 여기 있는가

`gds_us_remote`는 이 컨트롤러를 **원격에서 제어**하는 기기다. 기존 `gds_us_hmi`(PC HMI)는 읽기 전용이라 문제되지 않았지만, 원격 컨트롤러는 **FC06 파라미터 쓰기 + RESET/SEEK/START/STOP 명령**을 보낸다.

**원격 START는 물리적 기동이다.** 초음파 혼이 실제로 내려오고 용접이 일어나며, 그 시점에 조작자가 기기 앞에 없을 수 있다.

이 요구사항을 만족시키려면 **이 저장소의 펌웨어가 바뀌어야 한다.** 원격 프로젝트 혼자 할 수 없다.

## 2. 조사로 확인된 현재 상태

`gds_us_remote` 세션에서 이 저장소를 읽기 전용으로 조사한 결과다. **코드는 수정하지 않았다.**

| 확인 사항 | 근거 |
|---|---|
| **원격 제어를 활성화/차단하는 메커니즘이 없다.** Modbus 도달 가능한 누구나 언제든 `START(0x1B)`에 1을 쓸 수 있다 | `fw/include/app_modbus_core.h:15-44` — 레지스터 `0x00~0x1D` 어디에도 권한 게이트 없음 |
| `US_REMOTE`(`us_run_status`=1)는 **현재 운전을 무엇이 시작했는지** 나타내는 상태 표시값이다. 권한 게이트가 아니다 | `fw/include/app_lcd.h:67` |
| `app_modbus_note_remote()` / `remote_active()`는 유효 요청 후 1초간 true인 **LCD REMOTE 아이콘 점등용** 통신 활성 표시다 | `fw/include/app_modbus.h:34-40` |
| `EN_SAFTY(0x16)` / `cfg->f_safty`는 용접 트리거의 **양손 안전** 로직이다. 원격 권한과 무관 | `fw/include/app_weld_trigger_fsm.h` |
| **30초 절대 안전 상한이 유일한 무조건 backstop이다.** 주석에 이미 `stuck remote command`가 동기로 적혀 있다 | `fw/src/app_reg.c` `ON_TIME_SAFETY_MS 30000u` — 2026-06-27 사용자 결정 |
| `mb_write_reg`는 `addr < MB_REG_COUNT(50)`이면 **무조건 저장하고 에코한다.** 미사용 영역에 써도 "성공"하고 read-back까지 통과한다 | `fw/src/app_modbus_core.c:68-80` |
| `0x1E~0x31`(20개) 미사용 | `MB_REG_COUNT = 50` |

> ⚠️ 마지막 항목이 **안전에 직결된다.** 게이트가 없는 현행 펌웨어에 원격기를 붙이면, 원격기가 활성화 레지스터에 쓰고 성공 응답을 받아 **"활성화됐다"고 오판한 뒤 START를 보낼 수 있다.** 이를 막기 위한 capability probe가 설계에 포함돼 있다(§4).

## 3. 승인된 결정 (2026-08-02 사용자)

### 3.1 안전 정책

| 항목 | 결정 |
|---|---|
| **활성화 주체** | **컨트롤러 LCD 전용.** 기기 앞의 사람만 켤 수 있고 원격기는 상태를 읽기만 한다 |
| 근거 | 원격기가 자기 권한을 스스로 켤 수 있으면 게이트가 존재하지 않는 것과 같다. 활성화는 "기기 앞에 사람이 있고 원격 기동을 받아도 되는 상태임을 확인했다"는 **인간의 판단 기록**이며, 그 판단은 기기 앞에서만 내릴 수 있다 |
| 수명 | **비영속** — FRAM 저장 금지, 전원 재인가 시 소멸. 유한한 활성 창 + 링크 침묵 시 자동 해제 + E-STOP 시 강제 해제 |
| 가동 중 해제 | **신규 명령만 차단.** 진행 중인 런은 자연 종료시킨다 — 소프트웨어 판단에 의한 급정지가 오히려 더 위험할 수 있고, 30초 절대 상한이 backstop으로 남는다 |
| 게이트 범위 | **START / SEEK / RESET + cfg 쓰기.** `STOP`과 모든 읽기는 **무조건 허용**(안전 방향) |
| 게이트 위치 | `app_modbus_apply_writes()` — **`US_COMM` 경로만.** `app_reg` 쪽에 넣으면 로컬(LCD·물리 스위치) 조작까지 막힌다 |

### 3.2 파일럿 범위

**`gds_us_remote` 파일럿에서는 원격 START/SEEK/RESET을 전면 제외한다.** STOP·읽기·파라미터 쓰기만 사용한다.

→ 따라서 **이 게이트 펌웨어는 원격 프로젝트의 파일럿을 블로킹하지 않는다.** 일정 압박 없이 착수할 수 있다. 다만 **원격 START 허용의 유일한 선행**이다.

## 4. 이 저장소에 필요한 변경 (요구사항)

> 구현 방법은 이 저장소의 판단이다. 아래는 **무엇이 필요한가**만 적는다. 설계 정본은 §6 참고.

### 4.1 원격 활성화 게이트 (레지스터 `0x2A~0x2D`)

| addr | 이름 | 성격 |
|---|---|---|
| `0x2A` | `REMOTE_CAP` | capability probe. 미러가 매직값(예 `0x5201`)을 매 tick 복원 → 원격기가 write-then-readback으로 **신/구 펌웨어를 판별**한다. 구 펌웨어는 쓴 값이 그대로 남고, 신 펌웨어는 매직으로 복원된다 |
| `0x2B` | `REMOTE_EN` | 활성화 상태 + 해제 사유 (읽기) |
| `0x2C` | `REMOTE_EN_LEFT` | 잔여 활성 시간(초) |
| `0x2D` | (예약) | 향후 2단계 승인(원격 요청 → LCD 승인)으로 승격할 경로 |

필요한 작업:
- 활성화 상태 변수(비영속, `app_config_t`·FRAM 불가침) + 상태 머신
- 미러 패스에 위 레지스터 반영
- `app_modbus_apply_writes()`에 게이트 판정 삽입 (`US_COMM` 한정)
- 링크 침묵 감지 — 기존 `app_modbus_note_remote()`의 스탬프를 재활용 가능
- E-STOP 시 강제 해제
- **LCD 활성화 조작 UI** — 기존 입력 패턴(롱프레스 / 즉시-live 토글 / shadow→SAVE) 중 무엇을 쓸지, DGUS 화면 자산 변경이 필요한지 판단 필요 (미결: DG-16)

### 4.2 comm/ethernet 레지스터 확장 (레지스터 `0x1E~0x29`)

별도 결정(2026-08-01)으로, Modbus에 노출되지 않던 저장변수를 노출한다. `comm_address` / `comm_speed_idx` / `comm_parity_idx` / `comm_mode`(읽기 전용) / `ether_ip` / `ether_nm` / `ether_gw` + staging·commit 제어.

⚠️ **자기참조 위험**: comm/ethernet 설정은 그 값을 쓰는 데 사용하는 링크 자체를 제어한다. FC16 미지원이라 IP 주소를 원자적으로 쓸 수도 없다. 설계는 **staging + commit**이며, **커밋은 교차 경로에서만 허용**한다(RTU 접속 중 → ethernet 설정만, TCP 접속 중 → serial 설정만). `comm_mode` 원격 쓰기는 v1에서 금지.

### 4.3 미결 사항 (착수 전 결정 필요)

- **활성 창 길이와 링크 침묵 임계** — 매직 넘버로 정하지 않았다. 현장 작업 세션 길이를 근거로 협의 + 실측 필요
- **LCD 활성화 조작 UI 방식** — DGUS 자산 변경 여부 포함

## 5. 반드시 알아야 할 잔여 위험

이 게이트는 **물리 인터록의 대체재가 아니다.**

- 소프트 플래그는 **활성화 시점의 판단 기록**일 뿐, 그 이후 누가 위험구역에 들어갔는지 감지하지 못한다
- **Modbus에 인증이 없다.** 활성 창 안에서는 그 버스·네트워크의 어떤 마스터든 기동시킬 수 있다. 활성화는 컨트롤러 단위이지 특정 원격기 단위가 아니다
- **원격 STOP은 비상정지가 아니다.** 물리 E-STOP만이 비상정지다

승인된 것은 **설계 정책이며 안전 규격 적합성이 아니다.** 이 설계는 안전 기능(safety function)으로 credit 될 수 없고, 실기 적용 전 현장·안전 담당 확인이 필요하다. 운영 절차(활성화 = 현장 통제 책임 인수 규칙, 표지, 제어망 분리, 교육)로 보완해야 한다.

## 7. 계약 문서 갱신 순서

`gds_us_remote/docs/reference/modbus-contract.md`(레지스터 맵 정본, `gds_us_hmi`와 공유)는 **아직 갱신하지 않았다.** 순서는 다음과 같다.

```
이 저장소에서 펌웨어 구현 → 실보드 벤치 검증 → 계약 문서 갱신 → 원격기 구현
```

구현 전에 계약을 고치면 존재하지 않는 레지스터가 정본에 사실처럼 들어간다. `gds_us_hmi`도 같은 계약을 공유하므로 갱신 시 그쪽에 알릴 것.
