# 원격기 기능 동등성 — `gds_us_ctrl` 에 대한 요구사항

> **문서 요약**: `gds_us_remote`(ESP32-P4 원격 컨트롤러)의 목표가 **"컨트롤러의 모든 기능을 원격기에서 동일하게 구현한다"** 로 확정됐다(2026-08-30 사용자). 그러려면 컨트롤러 쪽에 **① 원격 활성화 물리 인터록 ② 현재 Modbus 에 없거나(comm·ethernet·calibration·센서·horn) 쓰기가 막힌(모델 선택·주파수) 값들의 노출 ③ 몇 가지 계약 보강**이 필요하다. 이 문서는 **무엇이·왜 필요한지와 수용 기준**만 적는다.
>
> 🔴 **구현 방법은 이 문서가 정하지 않는다.** 핀 선정·회로·펌웨어 구조·파일 배치는 **이 저장소가 정한다** — 소비 측(원격기)이 HW·보드 사정을 모르기 때문이다. 기존 관행과 같다: *"이 문서는 소비 측 관점의 제안 정본이고, 펌웨어 구현 정본은 그쪽 설계 spec 이다 — 두 문서가 갈리면 실코드를 가진 그쪽이 이긴다."*

**요청자**: `gds_us_remote` (`~/dev/work/gds_us_remote`)
**작성**: 2026-08-30
**원격기 측 정본**: `docs/superpowers/specs/2026-08-30-functional-parity-roadmap.md`(목표·3층 분해) / `2026-08-01-modbus-register-extension.md`(주소 배치·comm·eth 프로토콜) / `2026-08-02-remote-enable-safety.md`(게이트 의미론)

---

## 0. 왜 이 요청이 생겼나

원격기는 지금 컨트롤러를 **읽고, 세우고, setup1 4필드를 쓴다**. 목표가 "모든 기능 동일"로 바뀌면서 세 층으로 나눠 보니 **막고 있는 것이 대부분 컨트롤러 쪽**이었다:

| 층 | 원격기 현황 | 막는 것 |
|---|---|---|
| 관측 | RUN·setup1·setup2·프로파일 | **comm·ethernet·calibration·센서 상태·horn 모드에 레지스터가 없다** |
| 설정 | setup1 4필드 | 위와 같음 |
| 조작 | STOP 만 | **원격 활성화 게이트가 없다** (START·SEEK·RESET) |

원격기 쪽 화면 작업은 블로커가 없다. **목표 달성 시점은 사실상 이 문서의 항목들이 언제 되느냐로 결정된다.**

## 요청 A — 원격 활성화 **물리 인터록**

### 무엇이 필요한가

**컨트롤러에 물리 스위치(또는 그에 준하는 하드웨어 입력)를 두고, 그 상태를 Modbus 로 읽을 수 있게 해 달라.** 원격기는 그 값이 "허용"일 때만 물리 기동 명령(START·SEEK·RESET)을 보낸다.

### 왜

원격 START 는 **사람이 없을 수 있는 곳에서 기계를 돌리는 것**이다. 그래서 **기기 앞에 사람이 있어야 원격 기동이 가능하다**는 인터록이 필요하다.

⚠️ **원래 안은 "LCD 터치로 활성화"였고 2026-08-30 에 폐기됐다.** DGUS 자산 변경이 필요해 진행이 막혀 있었고, 무엇보다 **물리 스위치가 인터록으로서 더 낫다**(상태가 눈에 보이고, 화면 오조작으로 켜지지 않는다).

### 요구 (무엇)

| # | 요구 | 근거 |
|---|---|---|
| A-1 | 하드웨어 입력 1개로 "원격 허용" 상태를 만든다 | — |
| A-2 | 🔴 **스위치는 기계 쪽에 있어야 한다** | 원격기에 달면 원격기가 자기를 활성화하는 것이라 인터록이 무의미해진다 |
| A-3 | **레벨 방식. 시간 만료 없음** | 2026-08-30 결정 (a). 스위치는 상태가 보이므로 "켜고 잊는다" 전제가 사라진다. 레벨에 만료를 얹으면 조작자가 **"스위치는 켜 있는데 왜 안 되지"** 를 겪는다 |
| A-4 | **링크 침묵 시 해제는 유지** | 원격기가 조용해지면(≈10초) 허용을 내린다. 통신이 죽은 채 허용이 남는 것을 막는다 |
| A-5 | **E-STOP 시 해제는 유지** | 기존 설계 그대로 |
| A-6 | 이 상태를 **Modbus 로 읽을 수 있어야 한다** | 원격기가 버튼 활성/비활성과 **거부 사유**를 표시한다 |
| A-7 | 구 펌웨어 오판 방지 수단이 필요하다 | 원격기가 "이 컨트롤러가 게이트를 지원하는가"를 판별해야 한다. 기존 `REMOTE_CAP` probe 안이 이 역할 |

### 안 정해진 것 (이 저장소가 정할 것)

- **여유 입력 핀** — `docs/pinmap.md` 에 명시적 여유 목록이 없다. 회로도·보드 확인이 선행이다
- **스위치 종류·위치** — 키 스위치? 패널 내부? ⚠️ **테이프로 붙여 두면 영구 활성**이라는 대가가 있고, 그 방어는 소프트웨어가 아니라 **스위치 종류·위치**로 하는 것이 맞다
- 디바운스·읽기 주기·FSM 배치

### 기존 작업과의 관계

`feat/remote-enable-gate` 브랜치의 **T-1~T-4(상태·미러·apply 게이트·자동 해제)는 그대로 쓸 수 있다** — 게이트 로직은 허용이 어디서 오는지 알 필요가 없다. **T-5(LCD 활성화 조작 UI)만 폐기**되고 그 자리에 하드웨어 입력이 들어간다. 창 만료(600s)는 A-3 으로 사라진다.

## 요청 B — 지금 Modbus 에 없는 값들

### B-1. comm / ethernet — **이미 승인된 설계가 있다**

`comm_address`·`comm_speed_idx`·`comm_parity_idx`·`comm_mode` / `ether_ip`·`ether_nm`·`ether_gw`.

원격기 측 확장 스펙(`2026-08-01-modbus-register-extension.md`)에 **주소 배치·staging+commit 프로토콜·교차 경로 커밋 규칙·`CFG_STAT` 코드까지** 설계돼 있고 **사용자 승인(DG-11, 2026-08-16)까지 끝났다.** 이 저장소에도 설계 초안이 있다(`2026-08-16-comm-eth-register-extension-design.md`, 미검토).

**필요한 것은 구현이다.** 이것 없이는 원격기가 comm/ethernet 화면을 재현할 수 없다(관측조차 불가).

### B-2. calibration — **신규 요청**

`cal_val`·`freq_cal_val` (둘 다 `int16`).

⚠️ **2026-08-01 에 "컨트롤러 전용"으로 제외했던 것이 2026-08-30 에 번복됐다.** 목표가 "모든 기능 동일"이 되면서 포함으로 바뀌었다.

🔴 **원격기 쪽 조사에서 확인한 것 — 설계에 영향이 있다**: `cal_val` 은 표시 보정이 아니라 **제어 루프 입력**이다. `cal_val → reg_current_from_adc → disp_amp → reg_power_from_amp → curr_power → acc_energy → curr_energy → weld FSM 에너지 EXIT 판정` 사슬이 실재한다(그리고 `app_reg.c` 의 비사이클 가동 정지 판정에도 쓰여 **`US_COMM`·`US_REMOTE` 가동의 정지 시점까지 좌우**한다). `freq_cal_val` 은 표시 전용이 맞다.

→ **범위 밖 값이 표시가 아니라 기계의 정지 시점을 왜곡하므로 클램프가 필요하다**(C-3).

### B-3. 센서 상태 — **신규 요청**

STD RUN(TRIGGER 모드) 화면의 `SENSOR ON/OFF`. 현재 `STATUS(0x1D)` 어느 비트에도 없어 원격기가 읽을 수 없다.

### B-4. horn-down 모드 — **신규 요청 (관측 + 조작)**

🔴 **관측이 특히 급하다.** horn 모드에서는 **모든 소스의 START 가 차단**되는데(`US_COMM` 포함) 원격기는 그것을 **감지할 방법이 전혀 없다.** 결과적으로 원격 START 를 보내면 FC06 에코 정상·명령 레지스터 소거 정상·`STATUS` `us` 만 계속 0 — **성공한 전송과 구분되지 않는다.** 조작자에게는 "화면은 정상인데 명령이 안 먹는" 상태가 되고, 원격기가 사유를 표시할 근거가 없다.

**조작도 요청한다**(원격에서 horn 모드 on/off). 2026-08-30 사용자 판단으로 **일반 설정과 같은 급**으로 분류됐다 — 모드를 켜는 것만으로는 아무것도 움직이지 않고, SOL_DN 을 토글하는 것은 조작자의 양손 START 다. 따라서 **요청 A(활성화 게이트)에 종속시키지 않아도 된다.**

⚠️ 원격기가 알고 있는 성질 2가지: **모드 전이 시 솔레노이드가 무조건 꺼진다**(의도된 안전 조치로 이해하고 있다) / **모드가 영속되지 않는다**(재부팅 시 소실) — 후자는 원격기 UI 가 표현해야 하므로 유지되는지 알려 달라.

### B-5. 모델 선택 · 모델 주파수 **쓰기화** — 신규 요청

`MODEL_TYPE(0x18)` · `MODEL_FREQ(0x17)`.

**레지스터는 이미 있고 읽기도 된다.** 문제는 **쓰기다** — 현재 `mirror_live()` 가 매 tick `cfg` 값으로 덮는다(`app_modbus.c:100-101`, 주석도 *"read-only: mirror"* · *"overwrites writes"*). 원격기가 FC06 을 보내면 **에코는 정상인데 read-back 에서 옛값이 나온다.** 원격기 쪽은 read-back 재시도 상한에 걸려 `실패: 실측 N` 으로 정직하게 보고하므로 조용한 사고는 아니지만, **기능은 안 된다.**

⚠️ **원격기 측 확장 스펙은 이것을 "부작용이 커 별개 변경"이라며 범위 밖에 뒀었다**(sys_mode · LCD 페이지 라우팅 · DAC). **2026-08-30 에 목표가 "모든 기능 동일"로 확정되면서 포함으로 바뀌었다.** 부작용이 작아진 것이 아니라 **범위 결정이 바뀐 것**이므로, 실제로 열 수 있는지·어떤 가드가 필요한지는 **이 저장소의 판단**이다.

원격기가 알고 있는 파급 2가지(설계 참고):
- **`MODEL_TYPE` 은 원격기 화면 라우팅 전체를 바꾼다** — setup1 변형 · 탭 3단/4단 · RUN 화면 선택. 원격기는 스냅샷 추종으로 이미 설계돼 있어 값만 바뀌면 따라간다
- **`MODEL_FREQ` 는 출력 게이지 구간 매핑을 바꾼다** — 원격기는 그 매핑을 **컨트롤러 펌웨어에서 포팅**해 재현하고 있다(`app_lcd.c` 의 `ref_lv_*` 시드 로직). 값이 바뀌면 원격기도 재계산한다

**요청**: 두 레지스터를 **쓰기 가능**하게 해 달라(미러가 덮지 않도록). 가드가 필요하다면 이 저장소가 정하고, 원격기는 read-back 으로 결과를 확인한다.

### 주소 여유

원격기 측 배치안은 `0x2E`·`0x2F`(calibration) + `0x30`(horn 조작) + STATUS 비트 2개(센서·horn 관측)로 **예비 4칸 안에 들어간다**고 계산했다. **비트로 돌리면 레지스터를 안 먹는다**는 것이 요지다. 실제 배치는 이 저장소가 정한다.

## 요청 C — 계약 보강 3건

방법이 아니라 **계약**이라 여기 적는다. 원격기·`gds_us_hmi` 양쪽 디코더가 같은 규약을 써야 한다.

| # | 요구 | 왜 |
|---|---|---|
| C-1 | **`int16` ↔ 레지스터 인코딩을 계약에 명시** (calibration) | 명시하지 않으면 **음수 cal 이 65000대 양수로 읽히는** 조용한 사고가 난다 |
| C-2 | **`EN_SAFTY(0x16)` 를 0/1 로 정규화** | 현재 comm 쓰기는 정규화가 없어 **5 를 쓰면 5 가 저장**된다(FSM 은 `!=0` 판정). 원격기가 0/1 만 보내도록 하고 있지만 계약 쪽에서도 닫히는 편이 낫다 |
| C-3 | **calibration 에 클램프** | B-2 참고 — 범위 밖 값이 **에너지 종료 판정을 왜곡**한다. 범위는 이 저장소가 정한다 |

⚠️ 참고로 원격기는 **모든 쓰기에 read-back 을 건다**(RS-485 첫 write 간헐 무효 대응). 클램프가 걸리면 read-back 불일치로 조작자에게 **실측값이 정직하게 보고**된다 — 이미 실기로 확인된 경로다.

### 발견 사항 하나 (참고, 요청 아님)

Modbus `WORK_CNTL(0x01)=0` 카운터 리셋 가드가 **하위 워드만** 비교한다 — `work_cnt` 가 65536 의 배수면 리셋이 발동하지 않는 이론적 구멍이 있다. LCD 경로는 32비트 전체 비교라 정상. samd20 충실 포팅의 결과로 보이며, **고칠지는 이 저장소가 판단할 일**이다.

## 수용 기준 — 원격기가 무엇으로 "됐다"고 판정하는가

| 요청 | 원격기 측 확인 |
|---|---|
| A | 스위치 OFF 에서 원격 START 가 **거부되고 사유가 표시**된다 / ON 에서 수용된다 / 링크를 끊으면 허용이 내려간다 / E-STOP 에서 내려간다 / 구 펌웨어를 만나면 게이트 미지원으로 판별된다 |
| B-1 | comm·ethernet 값을 FC03 으로 읽어 **컨트롤러 화면과 일치**한다. 쓰기는 staging+commit 규칙대로 동작하고 **자기 링크를 끊는 커밋은 거부**된다 |
| B-2 | calibration 을 읽어 화면과 일치한다. **음수 값이 부호대로 해석**된다. 범위 밖 쓰기가 클램프되고 read-back 으로 드러난다 |
| B-3 | STD TRIGGER RUN 에서 센서 상태가 화면과 일치한다 |
| B-4 | horn 모드 on/off 가 원격에서 **읽히고**, 그 상태에서 원격 START 가 왜 안 먹는지 원격기가 **사유를 표시**할 수 있다 |
| B-5 | 원격에서 `MODEL_TYPE`·`MODEL_FREQ` 를 쓰면 **read-back 이 새 값으로 돌아온다**(미러가 덮지 않는다). 원격기 화면이 새 모델로 라우팅되고 게이지 구간이 재계산된다 |
| C | 인코딩·정규화·클램프가 계약 문서에 적히고 벤치로 확인된다 |

⚠️ 원격기 규율: **계약 문서(`gds_us_remote/docs/reference/modbus-contract.md`)는 펌웨어 구현 + 벤치 검증 후에만 갱신한다.** 제안 단계의 값을 계약에 적지 않는다.

## 우선순위 — 무엇이 무엇을 막는가

1. **B-4 관측(horn STATUS 비트)** — 가장 싸고(비트 1개) 지금 가장 나쁜 상태("보냈는데 안 먹힘"과 구분 불가)를 해소한다
2. **A (물리 인터록)** — 원격기 조작층 전체(START·SEEK·RESET)가 여기 걸려 있다. HW 리드타임이 있으니 일찍 시작할수록 좋다
3. **B-1 (comm/ethernet)** — 설계·승인이 끝나 있어 구현만 남았다. 원격기 C 탭이 여기 걸려 있다
4. **B-2·B-3 + C** — F-A 2차로 묶어도 된다
5. **B-5(모델 선택·주파수 쓰기)** — 레지스터가 이미 있어 **미러가 덮지 않게 하는 것**이 핵심이다. 부작용 판단이 필요해 마지막에 뒀다

**1·3·4 는 서로 독립이고 A 와도 독립**이다. 원격기 쪽 화면 작업과도 병렬이다.
